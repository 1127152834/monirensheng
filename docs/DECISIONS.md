# 决策记录

本文件记录决策的来源、适用范围与影响。新决定替代旧决定时追加记录并标记替代关系，不抹除历史。日期使用 Asia/Shanghai。

## D-001 · Twenty + 专用业务服务

- 日期：2026-10-30。
- 状态：方向已确认；具体技术路径待 M0 验证。
- 来源：迁移评估推荐，用户同意开始设计开发。
- 决定：Twenty 承担通用工作台；事务性办理规则、材料和外部任务由独立业务服务负责。
- 原因：旧系统的单在办、定稿、幂等和结果纠正不能仅靠通用 CRUD 等价替代。
- 影响：不深度修改 Twenty 核心；业务数据单一权威写入，摘要通过受控同步呈现。

## D-002 · 全员可看、负责人办理、管理员改派

- 日期：2026-10-30。
- 状态：用户明确确认。
- 决定：有模块查看权限的其他员工可以查看；客户设置负责人后只有负责人/管理员可修改、办理；管理员可处理全部客户并修改负责人。
- 影响：不是“非负责人不可见”；新权限覆盖客户资料、申请、材料、邮件业务写入及后台动作。旧项目不设置客户负责人的约定不再适用。
- 未决定：首次默认负责人、未分配客户、历史分配，见 Q-01。

## D-003 · 原生业务对象只读，业务命令受控写

- 日期：2026-10-30。
- 状态：采用的技术设计，等待 M0 实测。
- 决定：普通员工（包括负责人）使用原生列表读数据，通过扩展表单执行业务写。后端验证真实身份、功能权限和客户负责人。
- 原因：利用静态对象权限与独立业务授权，避免把可见字段当权限或依赖未核实的原生动态授权。
- 代价：受控字段不允许原生单元格随意编辑；必须封闭导入、共享、工作流、发信和 MCP 写旁路。
- 备注：不承诺未验证的企业版功能免费可用；不修改商业许可标记或绕过许可检查。

## D-004 · 纯翻译与业务推进分离

- 日期：2026-10-30。
- 状态：由已确认权限要求推导的实现决定。
- 决定：纯翻译只生成/读取译文及必要缓存；它不更新申请、创建补件或发信。AI 草稿、发送和业务结果更新受办理权限约束。
- 原因：旧“读懂邮件”可能自动改变申请结果，不能让非负责人借查看操作修改业务。
- 未决定：是否及如何保留独立的自动状态推进，见 Q-03。

## D-005 · 批量驾照建档与邮件 AI 纳入首版

- 日期：2026-10-30。
- 状态：用户明确要求。
- 决定：批量上传驾照、OCR 核对、查重及批量建档；来信翻译、中文意图起草英文、回译、人工编辑和确认发送全部进入首版。
- 影响：M2 的人工闭环只是阶段演示，不能替代 M1/M3 的正式首版交付。
- 兼容基线：旧系统格式、30 张上传/请求、20 MB 文件、100 项提交等是源码现状，需实际验证，不是用户承诺的永久上限。

## D-006 · 暂缓桌面自动化；排除 Hostinger

- 日期：2026-10-30。
- 状态：用户明确要求。
- 决定：允许联网；不做 Hostinger/建站；企业自动申请、指纹浏览器及其他桌面能力暂不动，后续另排。
- 影响：首版保留企业人工办理、州结果、EIN、材料及网关业务；不迁移或改动旧桌面执行器。

## D-007 · 独立目录及持续文档维护

- 日期：2026-10-30。
- 状态：用户要求记录目录；目录组织为实施选择。
- 决定：以 `company-helper-crm/` 为后续业务扩展目录，`docs/` 保存计划、规格、决策、进度、变更、日志及模板，独立 Git 版本管理。
- 影响：文档不混入 Twenty 上游，也不改动用户旧工作树；每次任务必须同步相关记录，不在日志中保留凭据或真实资料。

## D-008 · 历史数据和既有服务保护

- 日期：2026-10-30。
- 状态：采用的实施规则。
- 决定：M0 使用独立实例和合成资料；迁移保留源 ID、历史归因与定稿，按客户批次选择唯一写入口。
- 原因：当前工作目录与最新 main 不同，且外部发送/提交具有不可逆结果；不能因迁移重放业务。
- 影响：开发不在现有 localhost:3000 工作空间创建测试业务记录；生产版本及源数据清点属于 M0/M5 的明确任务。
