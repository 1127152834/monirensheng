# Company Helper CRM Milestone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Twenty 中交付支持批量驾照建档、客户负责人权限、企业人工办理、网关申请及邮件 AI 的内部业务系统。

**Architecture:** Twenty 提供原生只读业务视图与扩展入口。专用业务 API 是办理事实的权威写入方，校验功能权限、客户负责人、事务和幂等，再同步 CRM 摘要。OCR、邮件与文档渲染按独立任务执行。

**Tech Stack:** TypeScript、Node 24、Hono、React/Twenty SDK、Zod、PostgreSQL/Drizzle、Vitest、Playwright；应用源码部署，中间件 Docker。

**Spec:** [SCOPE.md](SCOPE.md)、[ARCHITECTURE.md](ARCHITECTURE.md)、[权限规格](specs/permissions.md)、[建档与邮件规格](specs/onboarding-and-mail.md)。

更新时间：2026-10-31（Asia/Shanghai）。本文是总路线；只有 M0 已展开为执行任务。后续阶段在依赖验证通过后单独编写执行计划，不将尚未验证的 SDK 接口写成确定实现。

## Global Constraints

- 可以访问外网；不迁移 Hostinger 和建站平台。
- 首版必须包含批量驾照建档、邮箱 AI 回复及翻译。
- 员工可按功能权限查看客户；有负责人的客户只能由负责人或管理员修改、办理；管理员可处理全部客户并改派负责人。
- 企业自动申请、指纹浏览器、代理/设备执行等桌面能力暂不迁移；首版保留企业人工办理记录。
- 纯翻译不能顺带推进申请状态。发送邮件、更新申请、写入补件属于独立业务动作。
- 每类业务字段只有一个权威写入方；测试和演练使用合成资料，不触发真实申请、付款或对外发信。

## Review Focus

1. 转交发生在页面打开或异步任务排队之后：旧负责人必须在真正写入/发送时失去权限（M0-04、M1、M3）。
2. 同一驾照重复提交、同批重复、关联他人负责客户：不重复建档，不通过覆盖字段或附件绕过负责人（M1）。
3. 非负责人调用翻译：可以获得授权范围内的译文，但不能更新申请、补件或发送（M3）。
4. 邮件发送已经被 SMTP 接受但响应丢失：进入结果待核实，不自动重发（M3）。
5. 导入历史资料触发现有自动化或丢失旧附件：停用有副作用导入触发器并保留历史快照与文件 hash（M5）。

| 阶段 | 目标 | 依赖 | 当前状态 |
|---|---|---|---|
| M0 | 版本、独立环境、扩展方式与权限技术验证 | 文档基线 | 未开始 |

## M0：验证技术路线

执行入口：[M0 任务计划](plans/2026-10-30-m0-foundation.md)。

- [ ] 固定 Twenty 与参考 company-helper 版本；记录线上部署 commit 尚待核对的差异。
- [ ] 建立独立开发实例/数据库，保留现有 localhost:3000 和生产数据不变。
- [ ] 验证一个 Twenty 扩展组件可安装、显示，并以支持的方式取得可验证用户身份。
- [ ] 验证业务对象的普通员工原生只读权限，封闭导入、工作流、MCP、共享等写旁路。
- [ ] 跑通 A/B/管理员三身份下的合成客户读、写、改派与并发检查。
- [ ] 确定 LOGIC_FUNCTION_TYPE=DISABLED 对所选扩展方式的影响；需要调整时只在独立验证实例实施并记录。

**交付物：** 独立开发配置、一个最小扩展组件、一条合成业务命令、可复现权限验证报告、确定的接口/运行时选择。

**退出标准：** A/B 都能读；A 只能处理 A 的客户；管理员能处理和改派；改派后旧 A 的写操作被服务端拒绝；真实用户身份不能由请求参数伪造。必须真实验证平台集成，不能只用业务 API 的 mock 测试宣布通过。

**未通过时：** 记录具体 SDK、身份或权限限制，修订技术方案，不导入真实资料，不以管理员 key 暴露到前端作为临时绕行。

## M1：客户、负责人和批量建档

目标目录：`apps/business-api/src/modules/customers/`、`modules/onboarding/`、`modules/documents/`、`apps/twenty-app/src/components/customers/`、`components/onboarding/`。

- [ ] 先确定 Q-01：首次负责人、未分配客户及历史客户分配规则。
- [ ] 建立客户办理档案、Person/Company 摘要、材料桶、版本与旧 ID 映射。
- [ ] 实现管理员改派与当前负责人校验；保留原始创建/提交/确认人的历史。
- [ ] 迁移多张驾照上传、逐项 OCR、原图核对、失败转录/重试与批量提交。
- [ ] 验证 HEIC 解码、上传链路限制、模型超时、默认并发及资源占用；覆盖 100 项提交和追加更大批次。
- [ ] 迁移重复提示、关联已有客户及差异字段选择；关联/写附件同样受目标客户权限限制。
- [ ] 提供客户详情、基础搜索、只读阶段、材料查看与受控编辑。

**交付物：** 可实际使用的客户与批量建档工作台；管理员可查看批次结果和分配负责人。

**退出标准：** 一批混合合成样本覆盖正常、模糊、反面、重复、非法格式和超限文件；成功项独立保存，失败项可重试；同一项重放不重复建客户；非负责人不能通过关联已有档案覆盖字段或附件。

**范围说明：** 现有上限 30 张/上传请求、20 MB/文件、100 项/提交、OCR 默认并发 3 是兼容基线，需验证资源占用。正反面联合识别、一图多人、PDF 不是既定首版范围。

## M2：人工办理完整闭环

目标目录：`apps/business-api/src/modules/filings/`、`modules/applications/`、`apps/twenty-app/src/components/filings/`、`components/applications/`。

- [ ] 确定 Q-02，清楚区分当前客户权限、申请业务负责人字段与历史操作人。
- [ ] 企业设立、州审批结果、EIN、证明文件按人工操作建完整记录。
- [ ] 开始网关申请经业务命令执行，锁客户并保证单在办。
- [ ] 保存字段及正式附件的不可变定稿，排除草稿箱。
- [ ] 实现补件、期限、处理记录、结束、获批/拒绝和结果纠正。
- [ ] 重算首个有效获批及客户完成；保持客户阶段和各申请状态独立。

**交付物：** 不依赖桌面端即可从客户档案完成企业记录到网关获批的人工办理链。

**退出标准：** 同时开始两次申请只能成功一次；修改现有资料不改历史定稿；获批纠正可正确重算客户完成；负责人转交后旧经办人不能继续操作；不触发外部自动提交。

## M3：邮箱、翻译与 AI 回复

目标目录：`apps/business-api/src/modules/mail/`、`apps/twenty-app/src/components/mail/`。

- [ ] 接入手工配置 IMAP/SMTP、邮件同步、会话、申请关联、附件与错误恢复。
- [ ] 提供纯翻译，和摘要/要求识别、申请状态写回分离。
- [ ] 迁移回复方向、中文意图生成英文草稿、中文回译、编辑与核对提示。
- [ ] 选择客户附件、展示确认页、人工发送，保留幂等和 unknown 结果核实。
- [ ] 客户转交后，旧草稿或排队任务不能借旧授权发送或修改业务。
- [ ] 决定 Q-03 后再接入有业务副作用的自动邮件处理；独立测试补件/状态去重与纠正。

**交付物：** 可供员工日常处理申请邮件的完整工作台，包括用户明确要求的翻译和 AI 回复。

**退出标准：** A/B 均可读取授权邮件与译文；非负责人不能起草/发送或借翻译推进业务；人工改稿后能识别回译过期；重复发送只发生一次；转交、附件移除、新回复和响应丢失分别有正确处理。验证使用隔离邮箱模拟器，不给真实客户发信。

目标目录：`apps/twenty-app/src/components/tools/`、业务文档渲染适配、通知与待办模块。

- [ ] 迁移卡头查询，保留数据来源/版本说明。

- [ ] 工具需要读取客户资料时检查查看权限；需要把输出挂入客户材料时检查办理权限。

- [ ] 决定 Q-04 的聊天历史处理方式，确保旧系统历史可查询。

**退出标准：** 客户业务和两类 Web 工具在当前范围内可用；账单渲染链路有实际验证；所有写入口遵守负责人规则；使用流程不依赖暂缓的桌面功能。

## M5：数据迁移、试运行与切换

目标目录：`scripts/migration/`、`tests/integration/migration/`、`docs/journal/` 中的演练报告。

- [ ] 核定生产实际数据来源、数据库迁移版本、文件存储位置、数量与运行中任务。
- [ ] 完成旧 ID/用户/负责人映射，不迁旧密码哈希或设备 token，不自动合并同名客户。
- [ ] 暂停目标实例有副作用的导入自动化，记录暂停前配置并规划恢复。
- [ ] 先小样本演练，再导入档案、企业、申请、历史、文件和定稿；按 hash 与关系对账。
- [ ] 核实 running/sending/unknown 等未决外部动作，避免导入重放。
- [ ] 按客户批次停旧写入、做增量、开放新写入；保留只读历史。
- [ ] 演练回退：导出切换后新增事实、对账并决定恢复哪个写入口，不丢失已发生外部结果。

**交付物：** 对账报告、上线检查记录、切换记录、回退演练、只读旧系统入口。

**退出标准：** 无缺失定稿/附件、无错误归属或重复外部动作；业务负责人分配明确；小批用户完成真实业务验收后再扩大范围。
